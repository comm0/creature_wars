    Coding Conventions

    C++

    • Everything in the core uses snake_case.
    • Classes, structs, enums and type aliases end with _t, for example game_t or position_t.
    • Function parameters end with _p and data members end with _.
    • The core must not include Qt headers. If you need Qt, the code belongs in the bridge.
    • Numbers a designer might want to change go to data, not into the code.
    • New logic in the core comes with a GoogleTest test when it can be tested in isolation.

    Qt bridge and QML

    • The bridge and everything QML sees use the usual Qt camelCase.
    • Import Qt modules without a version, for example import QtQuick. A versioned import hides newer properties.
    • Add pragma ComponentBehavior: Bound to files where a delegate, Loader component or layer.effect uses ids from outside.
    • Do not name your own properties like built in ones. Item already has left, top and similar anchor lines, and redefining them fails when the file loads.
    • Inside a scaled Scene give sizes in scene units with font.pixelSize and size. Felgo's sp() and dp() would scale a second time on phones.

    Comments

    Code should explain itself through names and structure. When something really is not obvious, a comment of a few words is enough, one sentence at most. Longer explanations belong in this documentation.

    Graphics

    • Everything uses the oblique projection: an object stands on its tiles anchored at the bottom right, height goes up and to the left at 45 degrees.
    • The light comes from the top left. Top faces are the brightest, east faces darker, south faces the darkest.
    • One pixel of art is one scene unit. A tile is 16 by 16, a creature frame 32 by 32.
    • Every image has a base version, a +hd version at twice the size and a +hd2 version at four times the size, scaled without smoothing.
    • Sprite sheets use TexturePacker JSON (Hash) with frames named <direction>_<index>.png, rows in the order north, south, west, east, one pixel of extrude and two pixels of padding.

    Commits

    Write commit messages in English with a short title and a few lines about what changed and why. The history is public, so it should read well to someone new to the project.
