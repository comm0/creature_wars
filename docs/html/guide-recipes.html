    Recipes

    Short step by step instructions for the changes people make most often.

    Add a creature

    1. Add an entry to data/creature_types.json with id, name, group (the race or a wildlife group), color and the stats health, attack, attackRange, visionRange and speed.
    2. Optional fields: markerColor for a small mark on the placeholder graphic, behavior (aggressive or fleeing), areaRadius and areaColor for area damage.
    3. If the creature has its own sprite sheet, add its id to the list in qml/components/CreatureSprites.js. Without that, it is drawn as a tinted placeholder box, which is fine for testing.
    4. To make a race able to produce it, add it to the units list of the race's base in data/base_types.json, see below.

    Let a base produce a unit

    Every entry in units of a base type has a creature, a tier and the gold, food and timeMs of one spawn. Tier 1 is available from the start. For higher tiers add a training object with the gold and timeMs of the research that unlocks the unit. A unit of tier N appears in the menu once the base reaches level N.

    Add a research path

    1. Add an entry to researches in data/tech_tree.json with an id, a name, an effect and a list of levels. Each level has baseLevel, gold, timeMs and value.
    2. Supported effects are baseRegeneration, baseHealthPercent, healingAura, baseDamagePercent, shotCount and baseRangeBonus. A new kind of effect needs a new research_effect_t value in backend/tech_tree.h and code in game_t::apply_base_stats or wherever the effect applies.
    3. Pick an icon for the research in the researchIcons map of qml/components/ActionCircle.qml. Without one, a plus icon is shown.

    Tune the balance

    Most balancing needs no code at all. Change the numbers in data and restart the game: base health and damage per level in base_types.json, unit stats in creature_types.json, costs and times in tech_tree.json and base_types.json, income in economy.json and AI behaviour in ai_profiles.json.

    Add a race

    A race is a base type plus its creatures. The data part is easy, but some code still lists the three current races by name:

    1. Add the creatures and a base type with a new group to the data files.
    2. Add a card for the race to the race list in qml/scenes/MenuScene.qml and a difficulty entry for it.
    3. Pass the difficulty of the new race in GameBackend::startMatch and in qml/Main.qml.
    4. game_t::start_match places exactly three match bases. A fourth race needs a fourth starting position there.

    Making races fully data driven is one of the planned improvements.

    Add a sprite sheet

    The quickest way is the import script, which packs the frames in the same format TexturePacker produces:

    1. Draw an animation strip of 96 by 128 pixels: 3 columns (idle and two walking frames) of 32 by 32, rows in the order north, east, south, west. Save it as <id>_animation_96x128.png. Add <id>_corpse_32x32.png for the corpse.
    2. Put both files into a folder named after the creature id, inside one source folder for all creatures.
    3. Run python scripts/import_creature_sprites.py <source folder>. It writes the packed sheet with extrude and padding, the JSON and the corpse in all three resolutions to assets/creatures/<id>/.
    4. Add the id to qml/components/CreatureSprites.js.

    If you pack the sheet with TexturePacker instead, use the JSON (Hash) format, frame names like south_1.png with rows north, south, west and east, one pixel of extrude and two pixels of padding, and export +hd and +hd2 at twice and four times the size.

    Regenerate the placeholder art

    The bases of all four levels and the placeholder creature come from a script:

    python scripts/generate_placeholders.py

    It draws grey boxes in the oblique projection and writes all three resolutions. The game tints them with the race colour at runtime.
