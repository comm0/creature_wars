    Building and Running

    Requirements

    • Felgo 4 SDK with Qt 6.8.3 and Qt Creator.
    • CMake 3.16 or newer and Ninja (both come with the SDK).
    • A C++20 compiler. On Windows the SDK ships MinGW 13.
    • Optional: ccache and lld are used automatically when they are installed.
    • Optional: Python 3 with Pillow for scripts/generate_placeholders.py.

    The game

    Open CMakeLists.txt in the Qt Creator from the Felgo SDK, select the Felgo desktop kit and run the appCreatureWars target. The first configure step downloads nlohmann/json, and GoogleTest when tests are enabled, so it needs a network connection.

    Debug builds open a second console window called Creature Wars Debug. It shows log messages and a line with the game tick time, the creature count and the dispatcher queue, which helps a lot when you look at performance.

    CMake options

    OptionDefaultEffect
    CREATURE_WARS_BUILD_APPONBuild the Felgo application. Turn it off to build only the core and tests.
    CREATURE_WARS_MAP_SIZE64x32Map size preset: 40x20, 48x24, 56x28 or 64x32.
    CREATURE_WARS_WARNINGS_AS_ERRORSOFFTreat compiler warnings as errors, as the CI does.
    CREATURE_WARS_ENABLE_CLANG_TIDYOFFRun clang-tidy on the core while building.
    CREATURE_WARS_ENABLE_CPPCHECKOFFRun cppcheck on the core while building.
    CREATURE_WARS_USE_CCACHEONUse ccache when it is found.
    CREATURE_WARS_USE_LLDONLink with lld when it is found.

    Core and unit tests

    The core builds without Qt and Felgo. That is also how the CI builds it:

    cmake -S . -B build/core -G Ninja -DCREATURE_WARS_BUILD_APP=OFF \
    -DCREATURE_WARS_WARNINGS_AS_ERRORS=ON -DBUILD_TESTING=ON
cmake --build build/core
ctest --test-dir build/core --output-on-failure

    The tests live in tests/ and use GoogleTest. They cover the dispatcher, the scheduler, the game clock, base orders, the map, the pathfinder, the AI planner and a few full games between AI players. Scheduler based logic is tested with fixed points in time, so the tests do not wait for real time to pass.

    Continuous integration

    .github/workflows/ci.yml builds the core with GCC and Clang, runs the tests under AddressSanitizer and UndefinedBehaviorSanitizer and runs clang-tidy and cppcheck. Warnings count as errors there, so build with CREATURE_WARS_WARNINGS_AS_ERRORS=ON before you push.

    This documentation

    The documentation is written in QDoc and lives in docs. With qdoc in your PATH (it comes with the SDK) build the docs target, or run it by hand:

    cd docs
qdoc creature_wars.qdocconf

    The HTML ends up in docs/html and is committed, so readers can open docs/html/index.html without building anything. Rebuild it after every change to the docs or to quoted code. Code snippets in the tutorial are quoted straight from the source files with \\quotefromfile, so they stay in sync with the code as long as the quoted lines keep existing.
