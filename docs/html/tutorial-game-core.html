    Tutorial 5: A Game Core Like an MMORPG Server

    All rules live in a C++ core without Qt. It works like the server of an online RPG such as The Forgotten Server.

    Why not in QML? A usual Felgo game would use a Timer and JavaScript. That is faster to write. We use a separate core because it can be tested without a window, it treats the player and the AI exactly the same, and it can move to a real server later.

    One game thread

    game_t runs the game in its own thread. QML never touches the game state. It only sends commands:

        void request_spawn_creature(
        std::string identifier_p,
        position_t position_p
    );
    void request_spawn_base(std::string identifier_p, position_t center_p);
    void request_order_base_action(std::string key_p);
    void request_start_match(
        std::string player_base_identifier_p,
        std::unordered_map<std::string, ai_difficulty_t> ai_difficulties_p
    );
    void request_attack_target(std::uint64_t id_p, std::uint64_t target_id_p);
    void request_walk_to(
        std::uint64_t id_p,
        position_t destination_p
    );
    void request_set_aggressive(bool aggressive_p);
    void request_set_time_scale(double time_scale_p);

    Example from the bridge:

    game_.request_walk_to(creature_id, position_t{column, row});

    Each call only queues a task. The game thread runs the tasks one by one, so the game logic needs no locks.

    Dispatcher and scheduler

    • game_event_dispatcher_t runs tasks in the order they arrive.
    • game_scheduler_t keeps tasks for a point in time: the game tick, income, production, research, wildlife.
    class game_scheduler_t
{
public:
    using time_point_t = std::chrono::steady_clock::time_point;
    using event_id_t = std::uint64_t;
    using event_t = std::function<void(time_point_t)>;

    event_id_t schedule(time_point_t time_p, event_t event_p);
    bool cancel(event_id_t id_p);
    void clear() noexcept;
    void delay_all(std::chrono::steady_clock::duration delay_p);
    std::optional<time_point_t> next_time() const noexcept;
    std::optional<time_point_t> time_of(event_id_t id_p) const noexcept;
    std::vector<std::function<void()>> take_due(time_point_t now_p);

    Example: run something in two seconds and cancel it again:

    const auto id = scheduler_.schedule(now + std::chrono::seconds{2}, [](auto time) {
    // happens two seconds later
});
scheduler_.cancel(id);

    In the game loop, due events go to the dispatcher. The scheduler never runs game code itself, like in TFS:

            collect_actions();

        for (auto& event : scheduler_.take_due(game_clock_.now())) {
            dispatcher_.enqueue(std::move(event));
        }

        dispatcher_.dispatch_pending();

    Game time

    game_clock_t turns real time into game time. Pause stops it, 2x and 5x speed it up. Scheduled events just follow.

    Rules as data

    Numbers live in data, not in code:

      "income": {
    "gold": {
      "amount": 1,
      "intervalMs": 1000
    },
    "food": {
      "amount": 1,
      "intervalMs": 10000
    }
  },
  "levelIncomeBonusPercent": 20

    Change a value, restart the game, done. No rebuild.
